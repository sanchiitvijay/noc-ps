# NOC Automation — Frontend API Documentation

This document describes the primary REST API endpoints required by the Frontend application. All endpoints natively return JSON.

Base URL (default): `http://localhost:8000`

---

## Global Authentication Flow

The backend employs **JWT (JSON Web Tokens)**. With the exception of `/auth/login` and `/auth/signup`, all routes require the token to be sent via the `Authorization` header.

**Header Format:**
```http
Authorization: Bearer <your_access_token>
```

A `401 Unauthorized` response indicates an expired or missing token. If so, prompt the user to re-authenticate (or build a silent refresh flow if you prefer to implement the refresh token logic).

---

## Error Handling & Standard Response Format

All API errors (whether generated by validation, business logic, or internal server issues) are returned in a standard, predictable JSON envelope. 

You do **not** need to parse different error formats for different endpoints.

**Standard Error Payload:**
```json
{
  "success": false,
  "message": "Human-readable error description",
  "data": null,
  "details": {
    "optional": "additional diagnostic info"
  }
}
```

### Common HTTP Status Codes
- **`400 Bad Request`**: Client-side logic errors.
- **`401 Unauthorized`**: Missing or invalid Bearer token.
- **`403 Forbidden`**: Valid token, but insufficient permissions (e.g., trying to access an Admin route as an Analyst).
- **`404 Not Found`**: Resource or endpoint does not exist.
- **`409 Conflict`**: Resource already exists (e.g., username taken).
- **`413 Payload Too Large`**: File upload exceeds `MAX_INGEST_FILE_SIZE_MB`.
- **`422 Unprocessable Entity`**: Request body or query parameters failed schema validation. The `details` object will contain a `validation_errors` array specifying the exact fields.
- **`500 Internal Server Error`**: Unexpected backend failure.

**Example 422 Validation Error Response:**
```json
{
  "success": false,
  "message": "Request validation failed",
  "data": null,
  "details": {
    "validation_errors": [
      {
        "loc": ["body", "password"],
        "msg": "String should have at least 8 characters",
        "type": "string_too_short"
      }
    ]
  }
}
```

## 1. Authentication

### 1.1 Login
**POST** `/auth/login`

Authenticates a user and returns an access and refresh token pair.

**Request Form Data (not JSON):**
Use `multipart/form-data` or `application/x-www-form-urlencoded`.
- `username`: string
- `password`: string

**Sample Curl:**
```bash
curl -X POST "http://localhost:8000/auth/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin&password=admin123"
```

**Response (200 OK):**
```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "user": {
    "id": 1,
    "username": "admin",
    "role": "admin"
  }
}
```

### 1.2 Signup
**POST** `/auth/signup`

Creates a new user profile.

**Request Body (JSON):**
```json
{
  "username": "noc_analyst1",
  "email": "analyst1@example.com",
  "password": "SecurePassword123!",
  "role": "analyst"
}
```

**Response (201 Created):** Same token structure as Login.

### 1.3 Logout
**POST** `/auth/logout`

*(Requires Bearer Token)*  
Logs the user out and invalidates the current session token (added to blocklist).

## 3. Log Querying

### 3.1 Get Logs
**GET** `/get-logs`

*(Requires Bearer Token)*  
Retrieves paginated event logs. 

**Query Parameters:**
- `device_id` (optional, int)
- `event_type_id` (optional, int)
- `severity` (optional, str) - e.g. "Critical", "Warning", "Info"
- `search` (optional, str) - Text search over message or raw detail.
- `page` (optional, int) - Defaults to 1
- `page_size` (optional, int) - Defaults to 50

**Response:**
```json
{
  "total": 134385,
  "page": 1,
  "page_size": 50,
  "data": [
    {
      "event_id": 123236587,
      "event_time": "02:25:17.687",
      "event_type_name": "Node Down",
      "severity": "Critical",
      "message": "SW-CORE-02 is down. 100% packet loss.",
      "device_id": 42,
      "device_name": "SW-CORE-02"
    }
  ]
}
```

## 4. Diagnostics & Analysis

### 4.1 Automated Analyst Error Info Panel
**GET** `/error-info`

*(Requires Bearer Token)*  
The core endpoint for the NOC Analyst dashboard. Returns a **single unified payload** containing:

- **Device info** (name, IP, type, site, vendor, location)
- **Event type** metadata (name, severity, category)
- **Historical tickets** — full ticket data from the master query (ticket fields + severity + frequency + device + event fields)
- **Recent error logs** — raw `event_logs` entries for the device + event type
- **Live diagnostics** — ping, traceroute (with hop list), DNS lookup
- **AI-generated solution** — Gemini LLM analysis (or rule-based fallback)

**Query Parameters:**
- `device_id` (optional, int) — preferred
- `device_name` (optional, str) — partial LIKE match, used if `device_id` not provided
- `event_type_id` (required, int)

> **At least one of** `device_id` **or** `device_name` **must be provided.**

**Sample Curl:**
```bash
curl -X GET "http://localhost:8000/error-info?device_id=42&event_type_id=1" \
```

## 5. Network Internal Diagnostic Actions

You can trigger manual diagnostic requests if you wish to run checks separately from the complete error info panel.

*(Requires Bearer Token)*

### 5.1 Traceroute
**POST** `/internal/traceroute`
**Body:** `{"host": "10.10.10.5"}`
**Response:** `{"host": "...", "hops": [...], "completed": true}`

### 5.2 Ping
**POST** `/internal/ping`
**Body:** `{"host": "10.10.10.5", "count": 4}`
**Response:** `{"host": "...", "reachable": true, "packet_loss_pct": 0, "avg_rtt_ms": 15}`

### 5.3 NSLookup
**POST** `/internal/nslookup`
**Body:** `{"host": "10.10.10.5"}`
**Response:** `{"host": "...", "addresses": ["..."], "reverse_lookup": "..."}`

## 6. Admin Tools

*(Requires Bearer Token with `role = admin`)*

### 6.1 Ingest Excel/CSV
**POST** `/admin/ingest-excel`

Uploads a new data dump file (Events or Tickets CSV). Spawns a background thread that populates the respective database tables so the API does not hang.

**Request (Multipart Form Data):**
- `file`: The `.csv` or `.xlsx` file.

**Response (202 Accepted):**
```json
{
  "message": "File accepted for ingestion.",
  "job_id": 1
}
```

### 6.2 View Activity Logs
**GET** `/admin/activity-log`

Retrieves a paginated list of all actions performed by users (populated by the `ActivityLoggerMiddleware`).

**Query Parameters:**
- `user_id`, `endpoint_path`, `page`, `page_size`
